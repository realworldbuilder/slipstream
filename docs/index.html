Camera node

Slipstream

A Raspberry Pi 5 with a Logitech C270 webcam that turns a USB camera into a network camera. Anything on the network can pull the feed: OBS, a browser, or a script.

The whole thing in one picture

Video flows left to right. The camera is opened exactly once, by ffmpeg; everything else reads from MediaMTX.

The hardware

One self-contained node. It runs headless: no monitor, keyboard or mouse in normal use, just power and Wi-Fi.

Nothing is exposed to the public internet. The node is reached over Tailscale or the local network only.

How each piece works

1. The camera hands over MJPEG

The C270 can't send uncompressed 720p at 30 fps over USB 2, so it compresses each frame as a JPEG inside the camera. That stream of JPEGs is MJPEG. It is easy to produce but large, and neither RTSP players nor browsers want it, so it has to be converted.

The camera is addressed by its /dev/v4l/by-id/… path rather than /dev/video0, so it is still found if the Pi numbers its devices differently after a reboot.

2. ffmpeg re-encodes to H.264

ffmpeg decodes the JPEGs and encodes H.264, the format OBS and browsers both play. The Pi 5 has no hardware H.264 encoder, so this runs on the CPU with libx264. The settings all trade picture efficiency for low delay and low CPU use:

SettingWhat it does
-video_size 1280x720 -framerate 30Asks the camera for its top mode.
-preset ultrafastThe cheapest encoding effort. Keeps the Pi's CPU comfortable at the cost of needing more bitrate for the same quality.
-tune zerolatencyThe encoder emits each frame as soon as it arrives instead of holding frames back to look ahead.
-g 30A full keyframe every 30 frames, which is once a second. A viewer who joins waits at most a second for a picture.
-b:v 3000k -maxrate 3000k -bufsize 1500kHolds the stream near 3 Mbit/s, with only half a second of slack, so the bitrate stays steady on the network.
-pix_fmt yuv420pThe colour format every player supports.

3. MediaMTX serves it

MediaMTX is a small stream server. It launches ffmpeg itself (runOnInit), receives the H.264 on the path cam, and re-serves the same stream in several protocols without re-encoding:

PortProtocolUsed by
8554RTSPOBS, VLC, ffmpeg, the health service's stills
8889WebRTCBrowsers, with low delay
8888HLSBrowsers, more delay but more forgiving (a MediaMTX default)
9997Control APIThe health service only; bound to localhost

If ffmpeg exits, for example because the camera is unplugged, MediaMTX starts it again (runOnInitRestart). Plug the camera back in and the stream returns on its own.

4. health.py answers "is it working?"

A small Python HTTP server on port 8080 with two endpoints:

EndpointReturns
/healthJSON: whether the stream is ready, whether the camera is plugged in, CPU temperature, uptime. Status 200 when the stream is up, 503 when it is not, so a monitor only needs the status code.
/still.jpgOne frame as a JPEG, or 503 if the stream is down.

The still is taken from the running stream, not from the camera. A V4L2 camera can only be opened by one program at a time, and ffmpeg already has it.

5. systemd keeps it alive

Two units, both enabled at boot and both set to restart two seconds after any exit: slipstream-mediamtx.service and slipstream-health.service.

Deploy

The Pi runs whatever is in this repository. From the Mac, in the repo folder:

rsync -a --exclude .git ./ slipstream:slipstream/ && ssh slipstream 'bash ~/slipstream/pi/install.sh'

install.sh installs ffmpeg and MediaMTX if they are missing, then installs and restarts the two services.

Where modes would fit

Today Slipstream has one fixed behaviour: 720p at 30 fps, tuned for low delay, always on. All of it lives in one ffmpeg command in pi/mediamtx.yml. A mode would be a named set of these choices:

ChoiceTodayWhere it is set
Capture size and rate1280×720, 30 fpsffmpeg input flags
Bitrate3 Mbit/sffmpeg -b:v, -maxrate
Delay versus qualityLowest delayffmpeg -preset, -tune, -g
OutputsLive stream onlyMediaMTX path settings (it can also record to disk)
When it runsAlwaysrunOnInit (MediaMTX can instead start ffmpeg only when someone is watching)
